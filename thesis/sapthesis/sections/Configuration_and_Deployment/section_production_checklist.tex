\section{Production Checklist}
\label{sec:production-checklist}

This section provides a comprehensive checklist for deploying the Cineca Agentic Platform to production environments. The checklist covers security configuration, database setup, observability integration, and scaling considerations.

\subsection{Pre-Deployment Validation}

Before deploying to production, execute the following validation steps:

\subsubsection{Health Check Verification}

\begin{lstlisting}[language=bash, caption=Verify health endpoints]
# Liveness check
curl -fsS http://localhost:8000/v1/health/live

# Readiness check (includes dependency checks)
curl -fsS http://localhost:8000/v1/health/ready

# Component health details
curl -fsS http://localhost:8000/v1/health/components | jq
\end{lstlisting}

\subsubsection{LLM Configuration Validation}

\begin{lstlisting}[language=bash, caption=Verify LLM configuration]
# Run LLM smoke test
make llm-smoke-test

# Expected output:
# Configuration:
# {
#   "status": "success",
#   "config_source": "database",
#   "instance_name": "phi3-mini",
#   "provider_model_id": "phi3:mini",
#   "device": "cpu"
# }
\end{lstlisting}

\subsubsection{Database Migration Verification}

\begin{lstlisting}[language=bash, caption=Verify database migrations]
# Check current migration status
cd db/postgres_control && alembic current

# Verify no pending migrations
cd db/postgres_control && alembic heads
\end{lstlisting}

\subsubsection{Metrics Endpoint Verification}

\begin{lstlisting}[language=bash, caption=Verify Prometheus metrics]
# Check metrics are exposed
curl -fsS http://localhost:8000/metrics | head -20

# Verify key metrics exist
curl -fsS http://localhost:8000/metrics | grep http_requests_total
curl -fsS http://localhost:8000/metrics | grep agent_runs_total
\end{lstlisting}

\subsection{Production Checklist Script}

The platform includes an interactive production checklist script that validates key production features:

\begin{lstlisting}[language=bash, caption=Running the production checklist script]
# Run the interactive checklist
bash scripts/deployment/production_checklist.sh

# The script validates:
# 1. Backend Toggle & Rollback (redis <-> memory)
# 2. Redis Durability (AOF/RDB configuration)
# 3. TTL Sanity (job expiration, idempotency)
# 4. Atomic Cancel Under Load
# 5. ETag Parity Across Backends
# 6. Index Hygiene (orphan cleanup)
# 7. SSE Resilience (reconnection handling)
# 8. Metrics & Alerts
# 9. Security Enforcement
# 10. Documentation Discoverability
\end{lstlisting}

\subsection{Post-Deployment Verification}

After deployment, verify the following:

\begin{enumerate}
    \item \textbf{HTTPS Access}: Verify TLS certificate is valid and HSTS header is present
    \item \textbf{Authentication}: Test OIDC login flow with production IdP
    \item \textbf{Authorization}: Verify RBAC scopes are enforced correctly
    \item \textbf{Rate Limiting}: Confirm rate limits are applied
    \item \textbf{Metrics}: Verify Prometheus is scraping and Grafana dashboards display data
    \item \textbf{Alerts}: Trigger a test alert to verify alerting pipeline
    \item \textbf{Logging}: Verify logs are being shipped to aggregation system
    \item \textbf{Backups}: Run and verify backup/restore procedure
\end{enumerate}

\subsection{Rollback Procedure}

In case of deployment issues, the platform supports rollback:

\begin{lstlisting}[language=bash, caption=Rollback procedure]
# Stop current deployment
docker compose down

# Restore previous image
docker compose pull previous-tag
docker compose up -d

# Rollback database if needed (CAUTION: may lose data)
cd db/postgres_control && alembic downgrade -1

# Restore database from backup if necessary
bash scripts/database/restore_database.sh backups/backup_YYYYMMDD.sql.gz
\end{lstlisting}

The deployment script (\texttt{scripts/deployment/deploy-production.sh}) includes built-in rollback prompts when verification fails.
