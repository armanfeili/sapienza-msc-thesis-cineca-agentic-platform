# Architecture

This document provides an overview of the **Agentic Platform** architecture, covering its core components, communication flows, and deployment topology.

---

## 1. High-Level Overview

The Agentic Platform is a modular system designed for **natural language to graph database** interactions, enriched with observability, compliance, and scalability features.

**Key Goals:**
- Convert natural language queries into executable Cypher queries for Memgraph.
- Allow extensible **MCP (Model Control Protocol) tools** for CRUD, search, and analytics.
- Support real-time monitoring, auditing, and role-based controls.
- Enable flexible deployment (local, staging, production, cloud).

---

## 2. Core Components

### 2.1 API Layer (FastAPI)
- **Purpose:** Exposes REST and WebSocket endpoints for client interaction.
- **Key files:** `src/main.py`, `src/api/`
- **Responsibilities:**
  - Accept NL (natural language) queries and structured MCP tool requests.
  - Route requests to the Orchestrator.
  - Handle authentication, authorization, and rate limiting.

---

### 2.2 Orchestrator
- **Purpose:** Core coordination logic.
- **Key files:** `src/orchestrator.py`
- **Responsibilities:**
  - Select and execute the correct MCP tool based on input.
  - Manage retries and fallbacks.
  - Enforce **agent role configurations** (`src/agent/roles.yaml`) and retry policies (`src/agent/retry.yaml`).
  - Collect usage metrics and traces.

---

### 2.3 MCP Tools
- **Purpose:** Modular, declarative tool definitions for graph operations and analysis.
- **Location:** `examples/tools/*.json`
- **Types of tools:**
  - CRUD (e.g., `crud_create_node.json`)
  - Schema discovery
  - Semantic search
  - System health
  - Custom analytics

---

### 2.4 Graph Database (Memgraph)
- **Purpose:** Primary data store for nodes and relationships.
- **Access:** via Bolt protocol (`7687`) and Memgraph Lab (`3000`).
- **Responsibilities:**
  - Store entities and relationships.
  - Execute Cypher queries generated by the system.
  - Support full-text search, schema introspection, and analytics queries.

---

### 2.5 Caching & Rate Limiting (Redis)
- **Purpose:** Improve performance and protect against abuse.
- **Responsibilities:**
  - Cache frequent queries.
  - Store persistent counters for rate limiting.
  - Serve as a message broker for optional async tasks.

---

### 2.6 Observability Stack (Prometheus + Grafana)
- **Purpose:** Monitor system health and performance.
- **Responsibilities:**
  - Collect metrics from API, Orchestrator, and Memgraph.
  - Provide dashboards (`docs/observability/*.json`).
  - Trigger alerts based on defined thresholds.

---

### 2.7 Security & Compliance Layer
- **Purpose:** Ensure GDPR compliance, data retention, and privacy-by-design.
- **Key files:** `docs/compliance/`, `src/security/`
- **Responsibilities:**
  - Audit logging (`src/security/audit.py`).
  - Personally identifiable information (PII) scrubbing (`src/security/pii_scrubber.py`).
  - Role-based data access.
  - Data retention enforcement.

---

## 3. Request Flow

```mermaid
sequenceDiagram
    participant Client
    participant API
    participant Orchestrator
    participant MCP Tool
    participant Memgraph
    participant Redis

    Client->>API: HTTP POST /query
    API->>Orchestrator: Pass NL or MCP request
    Orchestrator->>MCP Tool: Select and execute
    MCP Tool->>Memgraph: Execute Cypher query
    Memgraph-->>MCP Tool: Return data
    MCP Tool-->>Orchestrator: Processed response
    Orchestrator-->>API: Final output
    API-->>Client: JSON response
    API->>Redis: Cache result (optional)
````

## 6. Extending the Platform

To add a new MCP tool:

1. Create a JSON definition under `examples/tools/`.
2. Document the tool in `docs/api/mcp-tools.md`.
3. Update Orchestrator logic (if necessary) to recognize the tool.
4. Add automated tests for the tool.
